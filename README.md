# Local Support AI

Local Support AI — локальное desktop-приложение для Windows, которое помогает готовить ответы по тексту и скриншотам без cloud API и без отправки данных во внешний интернет.

Приложение работает по модели `offline-first`:
- генерация идёт через локальный `Ollama` на `localhost`
- OCR выполняется локально
- экспериментальный `FastAPI` backend работает как локальный API на `127.0.0.1`
- история, стили, аналитика и память качества хранятся в `SQLite`

## Что уже умеет

- современный интерфейс на `PyQt6`
- тёмная и светлая тема
- режим `Только текст`
- режим `Текст + локальная vision-модель`
- загрузка скриншота, drag & drop, вставка через `Ctrl+V`
- OCR через `EasyOCR` по умолчанию
- опциональная поддержка `PaddleOCR`
- генерация через локальный `Ollama`
- поддержка vision-моделей `qwen2.5vl`, `llava`, `minicpm-v`
- стили общения с обучением на примерах
- аналитика по обращениям, OCR и качеству ответов
- локальный `FastAPI` bridge для анализа обращения
- вкладка `Диагностика`
- экспорт PNG-диаграммы по темам обращений
- настройка устройства генерации `Авто / CPU / GPU`
- замер SLA генерации
- локальная память исправлений для OCR и ответов

## Как устроено самообучение

В проекте нет fine-tuning внешней модели. Вместо этого приложение учится локально через собственную память в `SQLite`.

### 1. OCR memory

После OCR можно:
- отметить результат как `OCR верно`
- исправить текст вручную и нажать `Сохранить исправленный текст`

Приложение сохраняет пары:
- как OCR распознал текст
- как пользователь его исправил

Если одинаковые OCR-ошибки повторяются, приложение начинает автоматически подчищать похожие фрагменты в следующих распознаваниях.

### 2. Style memory

Можно:
- обучать стиль на своих примерах
- сохранять удачные ответы в стиль
- сохранять исправленные ответы

Исправленные ответы получают повышенный вес и попадают в `priority_examples`, поэтому следующие генерации сильнее ориентируются именно на свежие и удачные формулировки.

### 3. Quality rules

Приложение собирает статистику по:
- OCR без правок / с правками
- ответам без правок / с правками

На основе этого перед генерацией формируются локальные правила качества. Например:
- не цепляться за шумный OCR дословно
- писать короче, если пользователь часто сокращает ответы
- не уходить в лишнюю официальность

## Аналитика

Сейчас приложение считает:
- количество сгенерированных ответов
- среднее SLA генерации
- самую долгую генерацию
- частые темы обращений
- OCR: сколько проверено, сколько без правок, сколько исправлено
- ответы: сколько проверено, сколько без правок, сколько исправлено

Также можно выгружать PNG-диаграмму по количеству обращений по темам.

## Локальный FastAPI backend

В проект добавлен экспериментальный `FastAPI` backend. Это не cloud API и не внешний сервис. Он запускается на этой же машине и принимает запросы только через локальный адрес:

```text
http://127.0.0.1:8000
```

Зачем он нужен:
- отделить desktop-интерфейс от логики анализа
- учиться backend-архитектуре на живом проекте
- тестировать анализ обращений отдельно от PyQt-интерфейса
- подготовить проект к будущему разделению на `UI -> local API -> analyzer/style/learning`

Текущая схема:

```text
PyQt app -> local FastAPI API -> CaseAnalyzer -> JSON response -> PyQt app
```

Сейчас backend используется для анализа обращения:
- `GET /status` — проверка, что локальный backend запущен
- `POST /echo` — учебный endpoint для проверки POST-запросов
- `POST /analyze-request` — анализ текста через реальный `CaseAnalyzer`

Если backend недоступен, desktop-приложение не падает: оно использует локальный анализ внутри PyQt-приложения.

Запуск backend для разработки:

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn main:app --reload
```

Swagger UI:

```text
http://127.0.0.1:8000/docs
```

## Приватность

В проекте нет:
- cloud inference
- внешних API
- телеметрии
- аналитики
- фоновых сетевых запросов в интернет

Дополнительно используются защитные механизмы:
- `LocalOnlySession` разрешает HTTP только к `localhost`
- `BackendClient` разрешает обращения только к локальному FastAPI backend
- `privacy_guard.py` блокирует не-localhost сетевые подключения на уровне Python-сокетов

Исключение:
- при первом запуске `EasyOCR` может автоматически скачать локальные OCR-модели
- после этого OCR работает из локального кэша

Если включить режим полной блокировки сети, даже `localhost` для `Ollama` будет отключён.

## Установка для разработки

Требуется Python 3.12+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python .\main.py
```

Если нужен `PaddleOCR`:

```powershell
python -m pip install -r requirements-optional-paddle.txt
```

После этого можно выбрать `paddleocr` в настройках приложения.

## Ollama

1. Установите Ollama для Windows: [ollama.com/download/windows](https://ollama.com/download/windows)
2. Убедитесь, что локальный API доступен на:

```text
http://localhost:11434
```

3. Проверьте список моделей:

```powershell
ollama list
```

### Рекомендуемая vision-модель

```powershell
ollama pull qwen2.5vl
```

Альтернативы:

```powershell
ollama pull llava
ollama pull minicpm-v
```

## OCR-модели

`EasyOCR` запускается с `download_enabled=True`, поэтому недостающие OCR-модели могут скачаться автоматически при первом OCR-запуске.

При желании модели можно подготовить заранее:

```powershell
.\scripts\prepare_easyocr_models.ps1
```

Или напрямую:

```powershell
python -c "import easyocr; easyocr.Reader(['ru','en'], gpu=False, verbose=True, download_enabled=True)"
```

Кэш EasyOCR находится здесь:

```text
%USERPROFILE%\.EasyOCR\model
```

## Сборка `.exe`

Быстрая сборка:

```powershell
.\scripts\build_exe.ps1 -Clean
```

Или напрямую:

```powershell
python -m PyInstaller .\LocalSupportAI.spec --noconfirm --clean
```

Готовый файл:

```text
dist\Local Support AI\Local Support AI.exe
```
